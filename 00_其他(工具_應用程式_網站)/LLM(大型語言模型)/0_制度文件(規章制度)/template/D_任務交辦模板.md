# 文件 D｜任務交辦模板（TASK_TEMPLATES）

> 版本：0.1（<建立日期>）
> 使用方式：交辦前複製對應模板填空。「相關檔案（只准讀這些）」與「驗收標準」是控 token 與控品質的兩個關鍵欄位，不得留空。變更/部署類用文件 H 第 1 章的模板。

---

## 模板 1：實作（新功能 / 新腳本）— 派給 W

```markdown
# 任務類型：實作
# 角色：W

## 目標（一句話）
<>

## 背景（≤3 行）
<>

## 相關檔案（只准讀這些）
- <路徑>

## 規格
- <輸入 / 輸出 / 邊界條件>

## 驗收標準（每條都要能被指令驗證）
1. <指令 + 預期輸出>

## 環境
引用文件 G v<版本>；本任務涉及主機：<>
```

```markdown
<>

- <可驗證的行為描述或測試指令>

## 相關檔案（只准讀這些）
- <路徑>

## 重構範圍
- 准動：<>
- 不准動：<>

## 驗收標準
1. 不變式全部通過：<指令>
2. <結構目標，如「函式長度 ≤ N 行」>
```

## 模板 3：研究（查資料 / 比較方案）— 派給 S，必要時升 W

```markdown
# 任務類型：研究
# 角色：S

## 問題（一句話）
<>

## 判斷用途
<這份研究要支撐什麼決策>

## 範圍
- 只查：<來源/目錄>
- 不查：<>

## 產出格式（固定）
- 結論（≤3 行）→ 依據（條列）→ 未確認事項

## 禁止
- 禁止修改任何檔案；禁止把整份原文貼進回報。
```

## 模板 4：審查（Code review / 設定審視）— 派給 R

```markdown
# 任務類型：審查
# 角色：R

## 審查對象
- <PR 連結 / diff / 檔案路徑>
- 變更摘要（交辦人填，≤3 行）：<>

## 審查重點（依序）
1. 正確性：<這次特別擔心的點>
2. 安全性：認證資訊是否硬編碼？對外暴露面是否擴大？<依專案填檢查點，如 bind 位址 / 防火牆 / port>
3. 一致性：是否違反制度文件 A~M？是否與既有筆記/skill 衝突？
4. [效能：<依專案填>]

## 產出格式（固定）
- 結論：通過 ✅ / 修正後通過 🔧 / 退回 ❌
- 問題清單：每項含「位置、問題、建議修法、嚴重度(高/中/低)」
- 高嚴重度為 0 才可標「通過」
- 若發現舊筆記/制度文件需要修正 → 直接列出應刪除與應替換的段落
```
