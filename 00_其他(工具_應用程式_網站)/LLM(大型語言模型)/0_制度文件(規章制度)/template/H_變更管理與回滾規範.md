## 第 2 章：標準順序（固定套路，不重新發明）

### 2.1 資料庫相關變更（schema、參數、版本）
1. **先冗餘後核心**：先在備援/次要節點執行並觀察 ≥ 1 個驗證週期，再動核心節點。
2. 核心節點的 DDL 屬正式核心寫入 → 一律 ⛔（文件 F 矩陣）。
3. 參數變更優先用可動態調整的方式（記得同步寫入設定檔），能不重啟就不重啟。

### 2.2 應用部署
1. feature 分支 → 開發機驗證 → PR → R 審查（文件 D 模板 4）→ 合併（⛔）。
2. 正式機：逐服務滾動更新，**不要**全停再起。
3. 驗證清單全過才收工；任一項不過 → 依回滾決策點直接回滾。

### 2.3 設定檔變更
1. 先備份（第 1 章快照）。
2. 改完 diff 給出對照，僅重啟受影響服務。
3. 同步更新文件 G 的欄位清單（若欄位有增減）。

## 第 3 章：備份與還原演練

**RPO/RTO 目標**（演練與 failover 的合格標準）：

| 系統 | RPO（最多可丟資料） | RTO（最多可停機） |
|------|--------------------|------------------|
| <核心資料系統> | ≤ <待填> | ≤ <待填> |
| <快取/無狀態系統> | <依設計標注，如「全部快取，屬預期」> | ≤ <待填> |

- 還原演練「合格」= 在 RTO 內完成還原 **且** 資料落差 ≤ RPO；任一超標 → 開 D 任務單檢討備份頻率或流程。
- 備份不等於可還原。**每 90 天**至少一次還原演練：取最近備份在非正式環境還原並驗證資料可查。
- 演練結果記入文件 G 第 7 節；逾期未演練 → S 在例行檢查中自動開 D 任務單提醒。
- 備份檔的刪除/覆蓋屬文件 F 第 1 章永久禁止項，AI 只可新增與驗證。
