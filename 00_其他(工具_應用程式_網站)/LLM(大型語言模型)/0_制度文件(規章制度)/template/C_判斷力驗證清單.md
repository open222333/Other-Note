# 文件 C｜判斷力驗證清單（JUDGMENT_CHECKLIST）

> 版本：0.1（<建立日期>）
> 使用方式：輕量模型（角色 S）逐項打勾。**規則只有一條：任何一項打不了勾，就執行該清單指定的動作，不自行推理繞過。**

---

## 清單 1：何時該升級任務（每完成一小步就跑一次）

全部為「否」才可以繼續留在目前角色；任一「是」→ 依文件 B 第 3 章升級。

- [ ] 這一步需要修改檔案，而我是 S？（是 → 升 W）
- [ ] 我已經對同一個錯誤做了第 2 次修復嘗試？（是 → 升 R）
- [ ] 這次修改會碰到高風險領域：<依專案填，如 DB 複寫設定 / schema / 認證 / 防火牆與對外 port>？（是 → 升 R）
- [ ] 我在兩個做法之間猶豫，而任務單沒有指定？（是 → 升 R）
- [ ] 我發現制度文件 A~M 或 README 的內容和現實矛盾？（是 → 升 R）

## 清單 2：何時算完成（回報「完成 ✅」前必跑）

**全部打勾才算完成**，缺一項狀態只能填「阻塞」或繼續做：

- [ ] 任務單的每一條驗收標準都以指令實際驗證過（非「理論上會過」）。
- [ ] 回報符合文件 B 第 5 章格式，欄位齊全。
- [ ] 環境有變動 → 文件 G 已同步更新。
- [ ] 推翻了舊筆記/舊觀念 → 已當場刪修（總則第 2 條）。
- [ ] 動過的檔案清單與實際 diff 一致。

## 清單 3：何時需要問使用者（狀態改為「阻塞 ⛔」並停手）

- [ ] 操作落在文件 F 矩陣的 ⛔ 欄。
- [ ] 需要花錢、開新服務、或影響專案外的系統。
- [ ] 任務單的驗收標準彼此矛盾或無法驗證。
- [ ] 需要的資訊在 G 中標示 `<待填>` 且無法從允許讀取的檔案取得。

提問一律用文件 F 第 4 章的固定格式。

## 清單 4：何時停止重試（防止 token 燒錢迴圈）

任一成立 → 停止重試，依 B 升級或依 K 開新 session：

- [ ] 同一錯誤訊息連續出現 2 次。
- [ ] 已嘗試 3 種不同做法仍未通過驗收。
- [ ] 修好 A 弄壞 B、修好 B 又弄壞 A（震盪）。
- [ ] 開始想「試試看繞過驗證/安全機制」（→ 這是升 R 的訊號，不是選項）。
