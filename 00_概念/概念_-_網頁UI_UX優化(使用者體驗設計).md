# 核心原則

- 降低認知負荷、提升操作效率，並確保跨裝置的無障礙與流暢度
- 不只追求視覺華麗，而是透過精準的資訊架構與微互動，讓使用者直覺地完成目標

# 1. 資訊架構與視覺層次（Visual Hierarchy）

使用者通常以「掃描（Scanning）」而非「逐字閱讀」的方式瀏覽網頁，清晰的視覺引導能大幅減少迷失感。

- **F 型與 Z 型閱讀動線**：將最重要的標題、核心價值主張與行動呼籲（CTA）放在視覺焦點上
  - 文字較多的頁面 → F 型佈局
  - 著陸頁（Landing Page）→ Z 型佈局
- **善用留白（Whitespace）**：適當的間距區隔不同功能區塊，避免畫面擁擠，讓視覺呼吸並突顯重點內容
- **字體排印與對比度**：
  - 建立明確的字級規範（如 H1 至內文的比例）
  - 內文行高設定為字體大小的 **1.4 至 1.6 倍**
  - 文字與背景具備足夠的色彩對比度

# 2. 導航與操作效率（Navigation & Efficiency）

減少使用者尋找功能與完成任務的步驟，是提升留存率的關鍵。

- **扁平化導航結構**：
  - 盡量讓使用者在 **3 次點擊內**找到目標資訊
  - 主選單項目控制在 **5 到 7 個**以內，避免過多選項造成「選擇癱瘓」
- **快捷鍵與命令面板（Command Palette）**：生產力工具或複雜後台導入 `Cmd + K`（或 `Ctrl + K`）全域搜尋與快捷指令面板，大幅提升資深使用者的操作速度
- **智慧表單設計**：
  - 單欄式表單，減少視線左右跳動
  - 即時驗證（Inline Validation）與自動填寫
  - 錯誤發生時明確指出問題與修正方式

# 3. 微互動與即時回饋（Micro-interactions & Feedback）

系統的每一次回應都能建立使用者的信任感與掌控感。

- **骨架屏（Skeleton Screens）取代轉圈圖示**：載入時顯示頁面輪廓，降低等待焦慮，讓載入感覺更快
- **樂觀更新（Optimistic UI）**：按讚、收藏、勾選待辦等操作先在介面即時呈現完成狀態，背景再同步送出 API 請求，消除網路延遲帶來的卡頓感（失敗時需回滾並提示）
- **明確的狀態提示**：
  - 按鈕設計懸停（Hover）、點擊（Active）與禁用（Disabled）狀態
  - 操作成功或失敗時提供不干擾視線的輕量提示（Toast Notification）

# 4. 響應式與無障礙設計（RWD & Accessibility）

確保網頁在各種螢幕尺寸與不同能力的使用者手中都能順暢運作。

- **行動優先（Mobile-First）與拇指熱區**：
  - 手機版將核心操作（底部導航欄、主要 CTA）放在單手握持時拇指容易觸及的區域
  - 可點擊區域不小於 **44 × 44 像素**
- **無障礙網頁規範（WCAG）**：
  - 圖片加上替代文字（Alt Text）
  - 支援全鍵盤操作（Tab 鍵順序與 Focus 樣式）
  - 避免僅依賴「顏色」傳達資訊（例如錯誤提示同時搭配圖示與文字）
- **深色模式（Dark Mode）適配**：
  - 提供跟隨系統設定的深色主題
  - 使用深灰色（如 `#121212`）取代純黑背景，並降低色彩飽和度，減少長時間閱讀的視覺疲勞

# 5. 設計方案評估與選擇建議

依專案階段與資源選擇合適的切入點：

| 優化策略 | 適用場景 | 預期效益 | 開發與維護成本 |
|---|---|---|---|
| **基礎可用性與效能優化**（RWD、骨架屏、表單驗證） | 所有網站，尤其是電商與內容平台 | 直接降低跳出率，提升轉換率 | 中低（前端框架多有現成元件支援） |
| **設計系統化（Design System）**（統一元件庫、色彩與字體規範） | 中大型產品、多團隊協作專案 | 保持全站體驗一致性，加速後續開發 | 高（前期需投入大量設計與工程建置） |
| **進階效率與個人化體驗**（快捷指令、深色模式、AI 智慧推薦） | SaaS 工具、高頻率使用的 Web App | 大幅提升重度使用者黏著度與滿意度 | 中高（需持續追蹤數據並迭代微調） |
