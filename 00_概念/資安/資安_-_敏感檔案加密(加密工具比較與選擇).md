```
重要、敏感檔案（帳密、金鑰、個資、合約、備份）要加密時，先決定「保護什麼、在哪裡、給誰解」，再選工具。

備份工具內建加密（restic、BorgBackup、rclone crypt）、密碼管理器（Bitwarden、1Password、KeePassXC）。
```

# 先決定要保護什麼

| 問題 | 影響選擇 |
|---|---|
| 保護的是**一個檔案**、**一個資料夾**、還是**整顆磁碟** | 單檔加密 / 資料夾加密 / 全磁碟加密 |
| 防的是誰：電腦遺失被拿走？雲端業者？同事？攻擊者入侵正在執行的主機？ | 全磁碟加密只防「關機狀態被拿走」，開機掛載後對入侵者無效 |
| 誰要能解開：只有自己、一個團隊、程式（CI / 伺服器） | 密碼 / 多收件人公鑰 / KMS 或機密管理服務 |
| 要不要放進 git、雲端硬碟、備份 | 選對 diff、同步、增量友善的工具 |
| 要不要證明「這份檔案是誰給的、沒被改」 | 需要簽章：GPG，或另外用 `ssh-keygen -Y sign`、minisign（age 不做簽章） |

# 類型比較

| 類型 | 保護時機 | 優點 | 限制 |
|---|---|---|---|
| 單檔加密 | 檔案本身，複製到哪都是加密的 | 最直接；可安全傳送、上傳 | 要用時得先解密成明文；明文檔要另外處理 |
| 設定檔 / 機密管理 | 存在 repo、設定檔時 | 可進版控、可稽核、可分權限 | 執行時程式拿到的是明文 |
| 磁碟 / 容器加密 | 關機、未掛載時 | 對使用者透明，全部都保護 | **掛載後對入侵者、惡意程式無效** |
| 資料夾逐檔加密 | 放在雲端 / 同步資料夾時 | 雲端業者看不到內容，同步只傳變動的檔案 | 檔案大小、數量、修改時間仍可見 |
| 備份工具內建 | 備份資料在異地時 | 加密 + 去重 + 增量 + 版本 | 只用於備份流程 |
| 密碼管理器 | 帳密與小型機密 | 好用、可共享、可跨裝置 | 不適合大型檔案 |

# 各工具說明與用法

## 單檔加密

### age

現代、簡單，沒有設定可以調錯；適合加密備份、傳送機密檔。不做簽章。詳見 [age 筆記](../../02_作業系統/Unix/Linux/Linux_工具/Linux_加密/Linux_工具_age(檔案公鑰加密).md)。

```bash
age-keygen -o key.txt                          # 產生金鑰
age -r age1... -o secret.txt.age secret.txt    # 用公鑰加密
age -d -i key.txt -o secret.txt secret.txt.age # 解密
```

### GPG（GnuPG）

功能最完整：加密、**簽章**、信任網、Email（OpenPGP）。Linux 發行版套件、git commit 簽章都用它。缺點是概念與選項多，容易設定錯。

```bash
# 用密碼加密（對稱加密）
gpg -c --cipher-algo AES256 secret.txt          # 產生 secret.txt.gpg
gpg -o secret.txt -d secret.txt.gpg             # 解密

# 公鑰加密
gpg --full-generate-key                         # 產生金鑰（互動式）
gpg --export -a alice@example.com > alice.pub   # 匯出公鑰給別人
gpg --import bob.pub                            # 匯入別人的公鑰
gpg -e -r bob@example.com secret.txt            # 加密給 bob
gpg -d secret.txt.gpg > secret.txt              # 用自己的私鑰解密

# 加密並簽章（對方可以驗證是你寄的、沒被改）
gpg -se -r bob@example.com secret.txt
```

### 7-Zip（AES-256）

要把加密檔交給不熟技術的人時最方便：對方用 7-Zip 輸入密碼即可解開。

```bash
# -p 會提示輸入密碼；-mhe=on 連檔名都加密（只有 .7z 格式支援）
7z a -p -mhe=on secret.7z secret_folder/
7z x secret.7z
```

- 要用 **.7z 格式**（AES-256）。`zip -e` / `zip -P` 產生的是 **ZipCrypto 傳統加密，已可被破解**，不要用於敏感資料。
- .zip 就算選 AES-256，檔名清單仍是明文；檔名本身敏感時要用 .7z + `-mhe=on`。

### OpenSSL enc（不建議，只在沒有其他工具時用）

```bash
# 加密 / 解密：一定要加 -pbkdf2 與足夠的 -iter（舊寫法沒加會用很弱的金鑰衍生）
openssl enc -aes-256-cbc -salt -pbkdf2 -iter 600000 -in secret.txt -out secret.txt.enc
openssl enc -d -aes-256-cbc -pbkdf2 -iter 600000 -in secret.txt.enc -out secret.txt
```

不建議的原因：

- `openssl enc` **不支援 AEAD**（例如 AES-GCM，會回 `AEAD ciphers not supported`），CBC 模式**沒有完整性驗證**：加密檔被竄改，解密時常常**不會報錯**，直接輸出被改壞的內容。
- 加解密兩端的參數（演算法、`-pbkdf2`、`-iter`）必須完全一致，檔案裡不會記錄，容易出錯。
- 實測：把 2,000 行加密檔中間改掉 1 個位元，解密 exit code 仍是 0，輸出內容有幾行被改壞（只有改到最後一個區塊時才會因 padding 錯誤報錯）。

## 設定檔與機密管理

### SOPS

加密 YAML / JSON / ENV / INI 設定檔的「值」，鍵名保留明文，所以放進 git 還看得懂結構、diff 也看得出改了哪個欄位。後端可用 age、GPG、AWS / GCP KMS、Azure Key Vault、Vault。

```yaml
# .sops.yaml（放 repo 根目錄）：哪些檔案用哪些金鑰加密
creation_rules:
  - path_regex: secrets/.*\.yaml$
    age: age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p
```

```bash
sops --encrypt secrets/prod.yaml > secrets/prod.enc.yaml   # 加密
sops --decrypt secrets/prod.enc.yaml                         # 解密到 stdout
sops secrets/prod.enc.yaml                                   # 直接開編輯器編輯，存檔自動重新加密

# 解密端用 age 私鑰：預設讀 ~/.config/sops/age/keys.txt（macOS：~/Library/Application Support/sops/age/keys.txt），或用環境變數指定
export SOPS_AGE_KEY_FILE=~/.config/sops/age/keys.txt
```

### git-crypt

在 git repo 裡指定的檔案 commit 時自動加密、checkout 時自動解密；沒有金鑰的人 clone 下來只看到加密內容。

```bash
git-crypt init
echo 'secrets/** filter=git-crypt diff=git-crypt' >> .gitattributes
git-crypt add-gpg-user alice@example.com    # 用 GPG 公鑰授權成員
git-crypt unlock                             # 有權限的人 clone 後解鎖
git-crypt status                             # 確認哪些檔案有被加密
```

- 整個檔案加密，diff 看不出內容改了什麼。
- **移除成員很麻煩**：已拿到金鑰的人仍能解開歷史版本，要換金鑰並視同機密已外洩；需要頻繁調整權限時改用 SOPS。
- `.gitattributes` 要在加入機密檔**之前**設定，否則機密已經以明文進到 git 歷史。

### Ansible Vault

```bash
ansible-vault encrypt group_vars/prod/vault.yml
ansible-vault edit group_vars/prod/vault.yml
ansible-vault view group_vars/prod/vault.yml
ansible-playbook site.yml --ask-vault-pass      # 或 --vault-password-file，密碼檔不要進 git
```

### HashiCorp Vault / OpenBao、雲端 KMS / Secret Manager

- 機密集中放在服務裡，程式執行時用身分（IAM、Kubernetes service account）去取，不必把機密存在檔案或環境變數中。
- 支援存取稽核、權限控管、輪替，Vault 還能產生短效的資料庫帳號（動態憑證）。
- 適合團隊、多服務、需要稽核的正式環境；個人或小專案用 SOPS + age 通常就夠。
- HashiCorp Vault 2023 年改用 BSL 授權；需要開源授權可用分支 OpenBao。

## 磁碟與資料夾加密

### LUKS（cryptsetup）

Linux 標準的磁碟加密，適合整顆硬碟、分割區、隨身碟、備份硬碟。

```bash
# ⚠ luksFormat 會清空整個裝置，裝置名稱務必確認（lsblk）
sudo cryptsetup luksFormat /dev/sdX
sudo cryptsetup open /dev/sdX secretdisk      # 輸入密碼後出現 /dev/mapper/secretdisk
sudo mkfs.ext4 /dev/mapper/secretdisk         # 第一次才需要建立檔案系統
sudo mount /dev/mapper/secretdisk /mnt/secret

sudo umount /mnt/secret
sudo cryptsetup close secretdisk

# 備份 LUKS 標頭：標頭損毀就算知道密碼也救不回資料
sudo cryptsetup luksHeaderBackup /dev/sdX --header-backup-file luks-header.img
```

### VeraCrypt

跨平台（Windows / macOS / Linux），可建立「加密容器檔」（一個大檔案，掛載後像一顆磁碟）或加密整個隨身碟；適合要在不同作業系統之間帶著走的機密。

### BitLocker / FileVault

Windows（BitLocker）與 macOS（FileVault）內建的全磁碟加密，筆電一定要開。**復原金鑰**要另外保存（不要只存在那台電腦上）。

### gocryptfs / Cryptomator

逐檔加密一個資料夾，適合放在 Dropbox、Google Drive、NAS 同步資料夾：雲端只看到加密檔，同步只傳有變動的檔案。

```bash
# gocryptfs（Linux / macOS）
mkdir cipher plain
gocryptfs -init cipher        # 設定密碼，會顯示 master key（要另外保存）
gocryptfs cipher plain        # 掛載：在 plain/ 讀寫的內容會加密存進 cipher/
fusermount -u plain           # 卸載（macOS 用 umount plain）
```

Cryptomator 有圖形介面，Windows / macOS / Linux / 手機都能用，適合非技術使用者。

## 備份工具內建加密

| 工具 | 特色 |
|---|---|
| restic | 加密（預設必開）、去重、增量、快照；支援本機、SFTP、S3、B2 等 |
| BorgBackup | 加密、去重、壓縮；常用於 SSH 遠端備份 |
| rclone crypt | 在雲端儲存上加一層加密，檔名也可加密 |

```bash
# restic：初始化會要求設定密碼（也是加密金鑰），遺失就無法還原
export RESTIC_REPOSITORY=sftp:backup@nas:/backup/restic
export RESTIC_PASSWORD_FILE=/root/.restic-password    # 權限 600
restic init
restic backup /etc /var/www
restic snapshots
restic restore latest --target /tmp/restore
```

## 密碼管理器

帳密、API key、恢復碼、小型附件（金鑰檔）最適合放密碼管理器：Bitwarden（可自架 Vaultwarden）、1Password（團隊共享方便）、KeePassXC（離線的加密資料庫檔）。不適合大型檔案或大量資料。

# 需求選擇建議

| 情境 | 建議 | 理由 |
|---|---|---|
| 加密單一檔案寄給同事 | age（對方給公鑰）或 GPG | 不用傳密碼；GPG 可同時簽章 |
| 加密檔交給不熟技術的人 | 7-Zip（.7z、AES-256、`-mhe=on`），密碼用另一個管道給 | 對方只需要裝 7-Zip |
| 伺服器定期備份加密 | restic / Borg；或 `tar | age -r 公鑰` | 伺服器只放公鑰，私鑰不在主機上 |
| 專案設定檔裡的密碼、token 要進 git | SOPS + age（或雲端 KMS） | 只加密值、diff 可讀、權限好調整 |
| 已經在用 Ansible | Ansible Vault | 與工具整合 |
| 團隊多服務、需要稽核與輪替 | Vault / OpenBao 或雲端 Secret Manager | 集中管理、短效憑證 |
| 筆電、隨身碟、備份硬碟 | BitLocker / FileVault / LUKS | 遺失時資料不外洩 |
| 跨作業系統帶著走的機密資料 | VeraCrypt 容器 | 三大平台都能掛載 |
| 雲端硬碟裡的敏感資料夾 | Cryptomator / gocryptfs | 雲端業者看不到內容 |
| 帳密、恢復碼、API key | 密碼管理器 | 好用、可共享、跨裝置 |
| 需要證明檔案來源與完整性 | GPG 簽章、`ssh-keygen -Y sign`、minisign | 加密不等於簽章 |

# 金鑰與密碼管理原則

- **金鑰和加密檔分開放**：私鑰、密碼不要和加密檔放在同一個地方（同一個 repo、同一顆備份硬碟）。
- **私鑰 / 復原金鑰要備份**：遺失 = 資料永久無法復原；備份放密碼管理器或離線媒體，並定期測試能不能真的解開。
- **伺服器只放公鑰**：加密備份時伺服器只需要公鑰，主機被入侵也解不開舊備份。
- **密碼與檔案走不同管道**：加密檔用 Email 寄，密碼就用電話、通訊軟體另外給。
- **定期輪替、離職即撤銷**：人員異動時更換金鑰 / 密碼，並重新加密；已外流的舊金鑰能解開的舊檔案視為已外洩。
- **機密不要進 git 明文歷史**：已 commit 的明文就算刪掉也還在歷史中，要清除歷史並**撤銷該機密**。
- **權限**：金鑰檔 `chmod 600`，目錄 `chmod 700`。

# 常見錯誤

| 錯誤 | 說明 |
|---|---|
| 以為開了全磁碟加密就安全 | 開機掛載後，入侵者、惡意程式看到的都是明文；伺服器機密還是要靠單檔加密或機密管理 |
| 用 `zip -e` 加密敏感資料 | ZipCrypto 已可被破解；改用 .7z（AES-256） |
| `openssl enc` 沒加 `-pbkdf2` | 舊版預設的金鑰衍生很弱，密碼容易被暴力破解；而且 CBC 沒有完整性驗證 |
| 解密後的明文檔忘了刪 | 用完就刪；在 SSD、journaling / CoW 檔案系統上 `shred` 不保證能真正抹除，最好一開始就只在加密磁碟或記憶體（例如 `/dev/shm`）裡處理明文 |
